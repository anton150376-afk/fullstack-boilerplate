# Contributing

Человеческая половина того, что `.claude/rules/*.md` говорит агенту.
Правила по месту — там; здесь — то, что касается только человека: ветки,
pull request, параллельная работа нескольких людей.

## Ветки и pull request

- Ветки `feat/*`, `fix/*`, `chore/*` от `main`. Прямые пуши в `main`
  закрыты — обязательная проверка для слияния ссылается на задачу
  `gate` из `.github/workflows/ci.yml` (настройка защиты ветки — в
  самом GitHub, не в этом репозитории; ни то, ни другое не проверено
  вживую, `docs/BACKLOG.md`, `B-261008-no-remote-repo`).
- Один pull request — одна связная работа. Ревью — один человек, не
  автор. При работе в одиночку роль ревью выполняет подагент `reviewer` в
  свежем контексте (`.claude/agents/reviewer.md`) — он не видел, как
  писался код.
- `.github/CODEOWNERS` назначает ревьюера по пакету (владелец сейчас —
  условный `@owner-placeholder`, заменить на настоящие логины/команды
  до первого реального pull request).
- Слияние со сжатием в один коммит (squash) — единая политика репозитория
  для всех pull request.

## Коммиты

Conventional Commits — подробности в `.claude/rules/git.md`.

## Что можно вести параллельно, а что — по одному

| Область                                        | Режим                                                                                    |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Разные пакеты и приложения                     | Параллельно — границы импортов и `turbo boundaries` не дают пересечься                   |
| `packages/contract`                            | По согласованию — домены разложены по файлам, но два человека в одном домене конфликтуют |
| Схема Prisma и миграции                        | По одному — см. ниже, самое узкое место                                                  |
| Токены `packages/tailwind-config`              | По согласованию — правка палитры задевает оба интерфейса                                 |
| Каталоги локализации                           | Параллельно при раскладке по доменам (по файлу на область)                               |
| `pnpm-lock.yaml` и каталог версий (`catalog:`) | По одному — см. ниже                                                                     |
| `.claude/rules`, `turbo.json`, гейт            | По согласованию через pull request — общие правила, меняющие поведение у всех            |
| `docs/BACKLOG.md`                              | Параллельно при схеме идентификаторов `B-<ГГММДД>-<слаг>`                                |

## Миграции базы данных

1. Перед генерацией миграции — подтянуть `main`, перебазироваться.
2. Одна миграция на pull request; несколько изменений схемы в одной
   работе собираются в одну миграцию.
3. Применённую миграцию не править никогда — исправление всегда новая
   миграция.
4. Если во время ревью в `main` попала чужая миграция — перебазироваться,
   удалить свою, сгенерировать заново, проверить на чистой базе.
5. Удаление и переналивка локальной базы — штатная операция, под неё
   есть скрипт и детерминированные сиды (появятся в Фазе 4).

## Lock-файл и каталог версий

- `pnpm-lock.yaml` не сливается руками никогда. При конфликте — версия из
  базовой ветки, `pnpm install`, закоммитить результат.
- Запись в lock-файл агенту запрещена разрешениями
  (`.claude/settings.json`), но саму процедуру разрешения конфликта
  всё равно выполняет человек.
- Изменение каталога версий (`catalog:` в `pnpm-workspace.yaml`) —
  отдельный pull request, не попутно с функциональной работой: он
  задевает все пакеты сразу.

## Два агента на одной машине

Каждой задаче — свой `git worktree`. Две сессии в одном рабочем дереве
затирают правки друг друга, и это не сразу заметно.

```bash
git worktree add ../boilerplate-feature-x feat/x
cd ../boilerplate-feature-x
pnpm install
```

Закончив работу: `git worktree remove ../boilerplate-feature-x`.

## Разделение локальных сред

Два человека одновременно — два набора контейнеров. Свой
`COMPOSE_PROJECT_NAME` на разработчика либо порты через
`docker-compose.override.yml` (в `.gitignore`, образец —
`docker-compose.override.yml.example`).

## Онбординг

Что установить и в каком порядке — `docs/guides/onboarding.md`.
Секреты (ключи Garage, токены) — из менеджера паролей, не из переписки
(`docs/operations/env-vars.md`).
