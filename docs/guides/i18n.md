> **Зачем читать:** добавить строку интерфейса или язык за один проход.
> **Кому:** кто пишет интерфейс на два языка.
> **Последняя проверка:** 2026-10-11.

## Что это

Пошаговая инструкция. Устройство `packages/i18n` и то, почему оно так
устроено — [docs/packages/i18n.md](../packages/i18n.md).

## Добавить строку

1. Выбрать домен (файл каталога) — существующий или новый
   (`packages/i18n/src/locales/<lang>/<domain>.json`).
2. Добавить ключ **в оба языка сразу** — `ru` и `en`.
3. Если строка считает что-то (файлы, дни, элементы) — переменная называется
   `count`, и в русском каталоге обязательны все четыре формы:
   ```json
   {
     "count_one": "{{count}} элемент",
     "count_few": "{{count}} элемента",
     "count_many": "{{count}} элементов",
     "count_other": "{{count}} элемента"
   }
   ```
   Английский — только `count_one`/`count_other`.
4. `pnpm check:i18n` — проверяет и парность ключей между языками, и полноту
   русских форм числа.

## Строки — только в каталогах, не в компонентах

Компонент не содержит текст на русском или английском напрямую — только
вызов `t("domain:key")`. Это требование правила `i18n.md` (Фаза 3).

Гейт проверяет его так. `pnpm check:i18n` разбирает `*.ts` и `*.tsx` в
`apps/web`, `apps/mobile`, `packages/ui-web`, `packages/ui-native`,
`packages/admin-kit` и `packages/ui-core` (без тестов) и считает
кириллические строки: текст между тегами JSX, значения атрибутов и любой
строковый литерал в коде, включая поля объектов вроде `label: "Заметки"`.
Исключение — файлы `packages/admin-kit/src/labels.ts` и
`packages/ui-core/src/labels.ts`: там лежат русские значения по умолчанию
библиотечных компонентов. Латиницу проверка не видит.

Проверка работает как «храповик». Количество вшитых строк по каждому
файлу сверяется с `scripts/i18n-hardcoded-baseline.json`:

- Файл с большим числом строк, чем в baseline, роняет гейт и называет
  строки с номерами.
- Файл с меньшим числом даёт заметку без падения. После переноса строк
  в каталоги обновите baseline:
  `pnpm exec tsx scripts/check-i18n.ts --update-baseline`.
- Новый файл с вшитой строкой роняет гейт, потому что в baseline для него 0.

Строку, которую переводить нельзя, разрешает комментарий `i18n-ignore` на
той же или предыдущей строке. Пример — названия языков на них самих:
`{/* i18n-ignore: название языка записано на нём самом */}` перед текстом
«Рус» в переключателе языка.

Сейчас baseline пуст (`{}`): все экраны и компоненты читают строки из
каталогов. Механизм остаётся на случай, когда новый код придётся временно
допустить с вшитой строкой.

## Что ещё проверяет `check:i18n`

- **Парность языков.** Набор ключей ru и en совпадает, у каждого `_one` в
  русском каталоге есть `_few` и `_many`.
- **Порядок ключей.** Ключи в каждом JSON-каталоге идут по алфавиту на
  всех уровнях вложенности (так конфликты слияния остаются построчными).
  Исправить порядок автоматически:
  `pnpm exec tsx scripts/check-i18n.ts --fix-order`.
- **Отсутствующие ключи.** Вызов `t("ключ")` или `t("пространство:ключ")` с
  ключом, которого нет в русском каталоге, роняет гейт и называет место.
- **Неиспользуемые ключи.** Ключ каталога, который не вызывается ни в
  одном нетестовом файле, роняет гейт. Вызовом считается `t(...)`,
  `tAdmin(...)`, `i18n.t(...)` и любая функция с именем вида `t`, `tXxx`.
  Пространство имён учитывается только у вызовов с префиксом
  (`t("files:title")`): вызов `t("title")` засчитывается ключу `title` в
  любом пространстве. Формы числа (`_one`, `_few`, ...) считаются одним
  ключом.

Динамические ключи (`t(`${prefix}.name`)`) проверка не видит. Если такой
вызов появится, она пропускает поиск неиспользуемых ключей и печатает
заметку со списком мест. Передавайте ключ литералом.

## Подписи библиотечных компонентов

`admin-kit`, `ui-web` и `ui-native` не знают про `react-i18next`: их
компоненты принимают подписи пропсом `labels` и по умолчанию показывают
русский текст. Типы подписей и значения по умолчанию лежат рядом с
компонентами (`packages/admin-kit/src/labels.ts`,
`packages/ui-core/src/labels.ts`).

Приложение передаёт переведённые подписи из каталога. Функции
`adminLabels(t)`, `bugReportLabels(t)` и `fileUploadLabels(t)` из
`@boilerplate/i18n` превращают пространство имён `admin` или `ui` в
готовый объект:

```tsx
const { t } = useTranslation("ui");
<FileUpload labels={fileUploadLabels(t)} requestTicket={...} confirmUpload={...} />;
```

Подпись, которая зависит от числа, задана функцией (`page(page, pageCount,
rowCount)`, `buildVersion(version)`), а в каталоге это обычный ключ с
интерполяцией. Форму числа для русского языка выбирает каталог, а не
компонент.

Чтобы добавить подпись:

1. Добавьте ключ в тип подписей и в значения по умолчанию пакета.
2. Добавьте ключ в `admin.json` или `ui.json` обоих языков.
3. Добавьте строку в `adminLabels`, `bugReportLabels` или `fileUploadLabels`.

Тесты `labels-catalog.test.ts` в `ui-core` и `admin-kit` сверяют русский
каталог со значениями по умолчанию: расхождение роняет гейт.

## Добавить язык

1. Создать `packages/i18n/src/locales/<lang>/` с теми же доменами, что у `ru`/`en`.
2. Добавить импорт в `packages/i18n/src/resources.ts`.
3. `pnpm check:i18n` сверит набор ключей с эталоном.

Новый язык с собственными правилами множественного числа (не как у русского)
описывается отдельно — `check-i18n.ts` сейчас умеет проверять полноту форм
только для `ru`; для другого языка со сложными формами (например, арабского)
понадобится расширить скрипт.

## Почему мобильному нужны полифилы, а вебу — нет

Hermes (движок React Native) не реализует `Intl.PluralRules` — без полифила
i18next молча показывает английские формы вместо русских, не падая с ошибкой
(грабля 26 задания). Поэтому `apps/mobile` импортирует
`@formatjs/intl-locale` и `@formatjs/intl-pluralrules` из точек входа
`/polyfill-force` в своём `_layout.tsx`, **до** первого вызова `createI18n()`.
Веб и сервер используют `Intl` движка JS напрямую — полифил не нужен.

## Частые ошибки

- Забыть один из языков при добавлении ключа — `check:i18n` упадёт.
- Переменная счёта названа не `count` — подстановка множественного числа не сработает.
- Вшить текст в компонент вместо `t()` — проверяется правилом `i18n.md` (Фаза 3).
