> **Зачем читать:** как выкинуть то, что не нужно новому проекту, без поломки гейта.
> **Кому:** кто только что создал проект из этого шаблона (`scripts/init-project.ts`).
> **Последняя проверка:** 2026-10-09.

Первое, что делают с коробочным решением в новом проекте — удаляют
ненужное. Без инструкции это вырезают топором и ломают проверки
(раздел "Фаза 12" задания, пункт 12.2.3). Для каждого случая ниже —
что убрать и какую проверку подправить, чтобы `pnpm gate` остался
зелёным.

## Убрать мобильное приложение

1. Удалить `apps/mobile` и `packages/ui-native` целиком.
2. `pnpm-workspace.yaml` — `apps/*`/`packages/*` остаются глобами,
   правка не нужна (отсутствующий каталог просто не попадёт в рабочее
   пространство).
3. `docs/packages/ui.md` — таблица паритета теряет смысл без
   `ui-native`; удалить файл или оставить как историческую запись (на
   вкус) и убрать `check:parity` из `scripts/done-gate.sh`.
4. `scripts/check-parity.ts` — сам скрипт уже возвращает «пропущено»,
   если `packages/ui-web`/`packages/ui-native` не существуют (см. его
   собственный код) — отдельно ничего не трогать, но строку
   `run_step "check:parity" ...` в `scripts/done-gate.sh` можно убрать,
   раз проверка больше никогда не делает полезной работы.
5. `docs/guides/testing.md` — убрать раздел про границу Vitest/Jest
   (без `apps/mobile`/`ui-native` Jest в репозитории не остаётся).
6. `.github/workflows/mobile.yml` — удалить файл.
7. `docker-compose.yml` — удалить сервис `mobile-web` и профиль
   `mobile-web`; `apps/mobile/Dockerfile` удаляется вместе с каталогом.
8. `AGENTS.md` — убрать строку `apps/mobile` из «Карты репозитория».
9. Проверить `packages/contract`/`packages/api-client`/`packages/devtools` —
   они платформенно-независимые, трогать не нужно.

## Убрать админку

1. Удалить `packages/admin-kit`.
2. `apps/web/src/routes/admin/` — удалить каталог целиком (ресурсы,
   индекс, страница состояния).
3. `apps/web/src/lib/api.ts` и подобные — проверить, не импортируют ли
   что-то из `@boilerplate/admin-kit` (на момент написания — только
   маршруты `admin/*`, остальной веб её не касается).
4. `packages/devtools`'s `PermissionsProvider` интеграция живёт именно
   в `admin-kit` — модуль M2 (`ROADMAP.md`) в таком случае подключает
   права напрямую в приложение, не через `admin-kit`.
5. `docs/packages/admin-kit.md`, `docs/apps/web.md`'s раздел «Админка» —
   удалить/сократить.

## Перейти на один язык

1. Раздел "Фаза 2" задания: решить, какой язык остаётся — обычно
   русский (основной язык этого шаблона) или английский.
2. `packages/i18n/src/resources.ts` — убрать вторую запись из
   `resources` (`en: {...}` или `ru: {...}`), `supportedLanguages`
   станет массивом из одного элемента.
3. `scripts/check-i18n.ts` — читает `supportedLanguages`/`resources` и
   сверяет, что ключи совпадают МЕЖДУ языками; с одним языком сверять
   нечего — скрипт либо продолжает проходить тривиально (нет второго
   языка для расхождения), либо, если он явно требует `length > 1`,
   нужно поправить его так, чтобы один язык не считался нарушением.
   Проверить фактическое поведение перед тем, как полагаться на него —
   не предполагать по этой инструкции.
4. `LanguageSwitcher` (`apps/web/src/components`, `apps/mobile/src/components`) —
   компонент выбора языка перестаёт быть нужен с одним языком; убрать
   из экранов, где он подключён.
5. `docs/guides/i18n.md` — переписать: без выбора языка инструкция
   «как добавить строку» остаётся, «как добавить язык» — нет.
6. Русские формы числа (`count_one`/`count_few`/`count_many`/`count_other`)
   остаются, если остаётся русский; для английского — `count_one`/`count_other`.

## Отказаться от файлов

1. Удалить `packages/storage`.
2. `apps/server/src/files/` — удалить модуль, убрать `FilesModule` из
   `app.module.ts`.
3. `apps/web/src/routes/files.tsx`, `apps/mobile/src/app/files.tsx` —
   удалить экраны; `ui-web`/`ui-native`'s `FileUpload` компонент
   остаётся непривязанным, если больше ничего его не использует —
   решить, удалять ли и его.
4. `packages/contract`'s `files.contract.ts` — убрать из
   `packages/contract/src/index.ts` (импорт, запись в объекте
   `contract`, `export *`).
5. `docker-compose.yml` — убрать сервис `garage` из основного набора,
   если ничто больше не использует S3-совместимое хранилище; проверить
   сначала, не использует ли его что-то ещё (на момент написания — нет).
6. `docs/operations/env-vars.md` — убрать строки `S3_*`.
7. Prisma-модель `UploadedFile` (`apps/server/prisma/schema/file.prisma`) —
   удалить, если на неё больше никто не ссылается (проверить связи в
   других `*.prisma`-файлах перед удалением).

## Отказаться от очередей

1. Очереди (BullMQ/Redis) используются журналом действий
   (`NotificationsService`/`notifications.processor.ts`) и уборкой
   брошенных загрузок (`maintenance.processor.ts`) — убедиться, что обе
   функции действительно не нужны, прежде чем убирать Redis целиком.
2. `apps/server/src/queue/` — удалить модуль, убрать `QueueModule` из
   `app.module.ts`.
3. `apps/server/src/redis/` — удалить, если Redis больше нигде не
   используется (health-проверка `/health/ready` тоже на нём завязана —
   убрать соответствующий индикатор).
4. `apps/server/Dockerfile`'s стадия `worker` и `docker-compose.yml`'s
   сервис `worker` — удалить, если воркер только исполнял задачи очереди.
5. `docker-compose.yml` — убрать сервис `redis` из основного набора.
6. `docs/operations/env-vars.md` — убрать `REDIS_URL`.

## После любого из пунктов выше

`pnpm gate` — обязательный последний шаг каждого пункта, не финал всей
уборки разом: правка, которая ломает гейт, откатывается или
исправляется раньше, чем делается следующая. `scripts/init-project.ts`
сам заканчивается прогоном гейта (раздел "Фаза 12" задания, пункт
12.2.1) — после него репозиторий уже в рабочем состоянии, а всё
описанное здесь — уже отдельные, осознанные решения.
