## Назначение

Право — строка `ресурс:действие`; роль — именованный набор прав.
Ядро (M2.1), управление через API (M2.2), права на экземпляры объектов
(M2.3), отражение в интерфейсах (M2.4). Полное описание, кандидатов
(CASL и альтернативы) и критериев приёмки — [ROADMAP.md](../../ROADMAP.md#m2-права-и-роли).

## Границы

**Входит:** вычисление плоского набора прав (прямое назначение + роли,
объединение, явные запреты), кеш в Redis со сбросом по версии, guard
и `can()` на сервере, управление через API, опционально — права на
конкретные записи (решается ADR этапа M2.1).

**Не входит:** аутентификация — отдельный модуль ([M1](M1-auth.md)),
M2 использует пользователя из его сессии, но не выдаёт токены сам.

## Точки интеграции

Уже заложено (Фаза 8):

- `PermissionsProvider` (`packages/admin-kit/src/permissions/provider.ts`)
  — интерфейс `can(permission)` с временными реализациями
  (`createAllowAllPermissions`/`createDenyAllPermissions`/`createAllowListPermissions`).
  `AdminLayout`/`DataTable`/`ResourceForm` держат только эту сигнатуру
  — M2 подключает настоящую реализацию без правок экранов.

Появится в этом модуле:

- `apps/server` — таблицы прав/ролей, guard, декораторы, сервис `can()`.
- `packages/contract` — схема управления ролями и правами.
- `ui-web`/`ui-native` — компонент-ограничитель (M2.4), парный.

## Открытые вопросы

- Нужны ли права на экземпляры объектов (M2.3) с первого этапа, или
  это отдельный, более поздний этап — решает ADR этапа M2.1 (сильно
  влияет на модель данных и стоимость проверки).
- Статус CASL и альтернатив на дату начала этапа — на дату задания
  (2026-10-07) Oso объявлена устаревшей в опенсорсе, Permify куплена
  FusionAuth (AGPL); проверить заново.
