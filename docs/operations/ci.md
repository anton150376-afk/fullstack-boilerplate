## Workflow'ы

- **`ci.yml`** — на pull request и push в `main`: `gate` (тот же
  `scripts/done-gate.sh --full`, что у агента, с сервисными
  контейнерами Postgres/Redis и Garage, поднятым вручную — GitHub
  Actions не умеет передавать `command:` сервисному контейнеру, см.
  комментарий в самом файле; ключ доступа генерируется на каждый запуск и
  передаётся Garage через `GARAGE_DEFAULT_*`, а шагу гейта — через outputs), `migrations` (применить миграции в чистую базу сервиса, сравнить её со
  схемой через `prisma migrate diff --from-config-datasource --exit-code`,
  затем `prisma migrate status`),
  `smoke` (сервер, собранный и запущенный так же, как в Docker-образе —
  `node --conditions=compiled apps/server/dist/main.js` — на настоящих
  Postgres 18 и Redis 8, затем `LOG_FILE=server.log bash scripts/smoke-api.sh`:
  здоровье, цикл задач, очередь, OpenAPI, цепочка багрепорта по `X-Request-Id`;
  при сбое в журнал шага печатается хвост журнала сервера),
  `build`, `boundaries` (`turbo boundaries`), `e2e` (Playwright для веба:
  собирает API и веб, применяет миграции, `pnpm --filter web e2e` в Chromium
  на настоящих Postgres и Redis; при сбое прикладывает следы Playwright,
  `apps/web/e2e`, `docs/apps/web.md`).
  Задача `gate` — обязательная проверка для слияния в `main` (настройка
  защиты ветки — отдельный шаг в самом GitHub, не в этом репозитории).
- **Гейт без сети.** `pnpm gate:offline` (`scripts/offline-gate.sh`) гоняет
  гейт с отключённым кешем turbo и модулем `scripts/block-network.mjs` в
  `NODE_OPTIONS`: любое соединение Node не на `127.0.0.0/8`, `::1` или
  `localhost` получает ошибку и попадает в журнал, а если журнал не пуст,
  скрипт завершается с кодом 1 даже при зелёном гейте. Бинарник turbo под
  блокировку не попадает (написан не на Node). Прогон полным гейтом
  (`--full`) на 2026-10-11: 422 с, попыток выйти наружу не было. В CI задача
  не подключена — запускайте при подозрении, что новый шаг гейта ходит в сеть.
- **`docs.yml`** — `pnpm check:docs` плюс проверка внешних ссылок
  (`lychee`, только на изменённых страницах в pull request) и сборка
  сайта документации (`apps/docs`, раздел "Фаза 10" задания, пункт
  10.3 — `docs/apps/docs.md`), артефактом на каждый прогон. Деплой по
  SSH на отдельный поддомен — не настроен, нет целевого хоста
  (`docs/BACKLOG.md`, `B-261008-no-remote-repo`).
- **`docker.yml`** — сборка и публикация образов (`server-api`,
  `server-worker`, `web`, `mobile-web`) в GitHub Container Registry при
  push в `main` или по тегу.
- **`mobile.yml`** — веб-экспорт `apps/mobile` артефактом на каждый
  pull request, который трогает мобильное приложение; нативная сборка
  через EAS — только по ручному запуску (`workflow_dispatch`), требует
  `EAS_TOKEN`.
- **`release.yml`** — по тегу `v*`: вызывает `ci.yml` и `docker.yml` как
  reusable workflows (один и тот же гейт, не копия шагов), затем
  черновик описания выпуска.
- **`claude.yml`** — см. ниже.

## Минуты GitHub Actions

У приватного репозитория на бесплатном тарифе минуты Actions ограничены, а полный `ci.yml` с Postgres,
Redis, браузером и `compose` расходует их быстро. Публичный репозиторий минут не ограничивает. Чтобы
тратить меньше:

- `claude.yml` запускается только по упоминанию `@claude` в комментарии.
- Задача `compose` (самая дорогая) идёт на push в `main` и по тегам, не на pull request'ах.
- Dependabot работает раз в месяц, минорные и патч-обновления идут одним pull request'ом.
- `ci.yml` и `docs.yml` отменяют предыдущий прогон той же ветки (`concurrency`).

## `claude.yml` — две ловушки

1. **Токен подписки привязан к конкретному человеку.** `claude-code-action`
   поддерживает и ключ API, и OAuth-токен подписки Claude — но подписка
   принадлежит одному аккаунту. Для репозитория, которым пользуется
   больше одного человека, нужен именно `ANTHROPIC_API_KEY` (ключ
   организации/проекта), не личный токен подписки кого-то одного.
2. **Штатный `GITHUB_TOKEN` не запускает CI на коммитах агента.** Если
   `claude-code-action` коммитит изменения, используя автоматический
   `GITHUB_TOKEN` раннера, события от этих коммитов не триггерят другие
   workflow (ограничение самого GitHub — защита от рекурсивных
   циклов CI). Это означает, что `ci.yml`/`docs.yml` не запустятся
   автоматически на пуш от самого Claude — нужен личный access token
   (PAT) или GitHub App токен, если это поведение не подходит.

Все шаги `claude.yml` условны по наличию `ANTHROPIC_API_KEY` — без
секрета шаги пропускаются, форки и pull request без доступа к
секретам репозитория не падают.
