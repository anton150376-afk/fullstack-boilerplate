> **Зачем читать:** устройство пакета локализации и почему русские формы числа — четыре ключа.
> **Кому:** кто подключает локализацию в приложении или добавляет домен каталога.
> **Последняя проверка:** 2026-10-11.

## Что это

`i18next` с плоскими JSON-каталогами, общий для веба, мобильного и сервера.
Один и тот же импорт работает под Vite, под Metro и в Node для писем и
текстов ошибок — шага сборки нет.

## Состав

| Путь                               | Назначение                                                                                 |
| ---------------------------------- | ------------------------------------------------------------------------------------------ |
| `src/locales/<lang>/<domain>.json` | Каталоги по доменам (раздел 7.5 задания — конфликты слияния построчные, а не на весь файл) |
| `src/resources.ts`                 | Статический импорт каталогов в один объект `resources`                                     |
| `src/init.ts`                      | `createI18n()` — синхронно готовый экземпляр i18next                                       |
| `src/format.ts`                    | Обёртки над `Intl` для дат, чисел, относительного времени                                  |
| `src/i18next.d.ts`                 | Типы ключей перевода — выводятся из каталога `en`                                          |

## Русские формы множественного числа — четыре ключа

`_one` (1, 21, 31), `_few` (2–4, 22–24), `_many` (0, 5–20, 25–30), `_other`
(только дробные). Переменная — всегда `count`. Пример (`locales/ru/files.json`):

```json
{
  "count_one": "{{count}} файл",
  "count_few": "{{count}} файла",
  "count_many": "{{count}} файлов",
  "count_other": "{{count}} файла"
}
```

Английский каталог обходится двумя: `count_one`/`count_other`.

**Проверено намеренным нарушением:** если у `count_one` в русском каталоге
убрать `count_few`/`count_many`, `pnpm check:i18n` падает с указанием, какого
именно ключа не хватает. Runtime-тест `src/init.test.ts` отдельно проверяет,
что `i18next` реально выбирает нужную форму («1 файл», «2 файла», «5 файлов»,
«21 файл») — это ловит ошибки в самих значениях CLDR, которые
`check:i18n` не видит (он проверяет только наличие ключей, не текст).

## Почему полифилов `Intl` здесь нет

В Hermes (движок React Native) нет `Intl.PluralRules`, `Intl.RelativeTimeFormat`,
`Intl.ListFormat` и `Intl.Locale` (грабля 26 задания). Полифилы
`@formatjs/intl-locale` и `@formatjs/intl-pluralrules` нужны только
мобильному приложению — импортировать их здесь означало бы тащить лишний вес
в веб и на сервер, где они не нужны. `apps/mobile` импортирует их из точек
входа `/polyfill-force` **до** вызова `createI18n()` (Фаза 7).

## Подписи для библиотечных компонентов

Пространства имён `admin` (подписи `admin-kit`) и `ui` (багрепорт и загрузка
файлов в `ui-web` и `ui-native`) собраны в `adminLabels(t)`,
`bugReportLabels(t)` и `fileUploadLabels(t)` (`src/labels.ts`). Функции
превращают ключи каталога в объекты, которые компоненты принимают пропсом
`labels`. Тест `labels.test.ts` проверяет, что в обоих языках не осталось
непереведённого ключа. Порядок добавления подписи —
[guides/i18n.md](../guides/i18n.md).

## Добавить домен каталога

1. Создать `src/locales/ru/<domain>.json` и `src/locales/en/<domain>.json`.
2. Добавить импорт и запись в `src/resources.ts`.
3. `pnpm check:i18n` — наборы ключей между языками сверяются автоматически.

## Частые ошибки

- Забыть `_few`/`_many` у русского ключа с `_one` — ловит гейт.
- Назвать переменную счёта не `count` — i18next не применит правило
  множественного числа, подстановка просто не сработает.
- Импортировать полифилы `Intl` в этом пакете — лишний вес для веба и сервера.
