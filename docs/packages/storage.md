> **Зачем читать:** устройство адаптера хранилища и почему у него ровно четыре метода.
> **Кому:** кто работает с загрузкой файлов на сервере.
> **Последняя проверка:** 2026-10-11.

## Что это

Адаптер S3-совместимого хранилища на четыре метода —
`createUploadTicket`, `getDownloadUrl`, `head`, `delete`. Этот размер
важен: он и переживает смену поставщика (решение D16 задания). Единственная
реализация на сегодня — `createS3StorageAdapter` (`src/s3-storage-adapter.ts`),
обслуживает и Garage в разработке, и совместимых поставщиков в проде.

## Почему только подписанные формы POST

Подписанный PUT не ограничивает размер загрузки — размер в подписанной
ссылке можно ограничить только заголовком `Content-Length`, а клиент его
просто не отправляет (грабля 30 задания). `createUploadTicket` возвращает
подписанную форму POST: политика (`content-length-range`, тип содержимого)
входит в саму подпись, и хранилище отвергает нарушение самостоятельно —
не нужно доверять ни клиенту, ни серверному коду, который формировал
ссылку.

## Два адреса хранилища

В контейнере сервер видит хранилище как `http://garage:3900`, а браузер и
мобильное приложение — как `http://localhost:3900`. Подписанные URL уходят
клиенту, поэтому `S3StorageConfig.publicEndpoint` задаёт адрес для них, а
`endpoint` остаётся для запросов самого сервера (`head`, `delete`).

Для этого адаптер держит два клиента S3. Подмены адреса в готовой строке
недостаточно: хост входит в подпись ссылки на скачивание, и подменённая
ссылка перестала бы проходить проверку. Подпись формы POST от хоста не
зависит, но клиент общий, поэтому проще и надёжнее подписывать обе ссылки
клиентом с публичным адресом. Подпись выполняется локально, сеть для неё не
нужна, так что публичный адрес не обязан быть доступен серверу.

Приложение задаёт публичный адрес переменной `S3_PUBLIC_ENDPOINT`.

## Контрольные суммы AWS SDK

Начиная с версии 3.729.0 AWS SDK отправляет контрольные суммы CRC32 на
всех `PUT` и проверяет их на `GET` по умолчанию (`WHEN_SUPPORTED`) —
ломает S3-совместимые серверы, которые не являются AWS (Garage, другие).
`createS3StorageAdapter` явно задаёт `requestChecksumCalculation` и
`responseChecksumValidation` в `"WHEN_REQUIRED"` — без этого загрузка в
Garage отказывает на уровне самого SDK, раньше, чем запрос дойдёт до сети
(грабля 29 задания).

## Как протестирован без реального хранилища

`createUploadTicket`/`getDownloadUrl` подписывают запрос локальной
криптографией (HMAC по учётным данным) — не трогают сеть, поэтому
`s3-storage-adapter.test.ts` вызывает их по-настоящему, без мока, и
проверяет содержимое подписи (условие `content-length-range`, тип
содержимого, различие политики при разных `maxBytes`).

`head`/`delete` делают настоящий сетевой вызов — для них
`createS3StorageAdapterFromClient(client, config)` принимает готовый
`S3Client`, что позволяет тестам подставить мок и проверить обработку
результата (включая `NotFound` → `null`) без сети. Интеграционный тест
против реально поднятого в `docker-compose` хранилища — отдельная задача
(`docs/BACKLOG.md`, `B-261008-docker-unverified`), не прогонялась на этой
машине.

## Частые ошибки

- Доверять размеру или типу, заявленному клиентом при выдаче талона —
  сервер обязан перепроверить оба после подтверждения загрузки
  (`apps/server/src/files/files.service.ts`, настоящий тип — по сигнатуре
  файла, не по расширению).
- Забыть `WHEN_REQUIRED` при переходе на новую версию AWS SDK — проверить
  актуальность дефолта перед обновлением (грабля 29 задания).
- Серверу в продакшене нужны скомпилированные файлы пакета: у каждой точки
  входа есть условие `compiled` → `dist/*.js` (скрипт `build`,
  `tsconfig.build.json`), сервер запускается как
  `node --conditions=compiled`. Поэтому `exports` содержит три ключа —
  `types`, `compiled`, `default`; не сводите их к одному
  (`docs/architecture/monorepo.md`, раздел «Условие compiled»;
  `pnpm check:runtime` проверяет это в гейте).
