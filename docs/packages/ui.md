> **Зачем читать:** какие компоненты обязаны существовать в обеих
> платформенных реализациях и где между ними допустимая расходимость.
> **Кому:** кто добавляет компонент в `ui-core`/`ui-web`/`ui-native`.
> **Последняя проверка:** 2026-10-11.

## Таблица паритета

| Компонент         | `ui-web`                                                                                                                            | `ui-native`                                                                                                                           | Расхождения                                                                                                                                                            |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Button`          | `@base-ui/react/button`                                                                                                             | `Pressable` + `Text`                                                                                                                  | Нет — пропсы `variant`/`size`/`children` совпадают, `onClick` vs `onPress` — платформенное                                                                             |
| `FileUpload`      | `<input type="file">` + `XMLHttpRequest`                                                                                            | `File.pickFileAsync` + `file.upload` (expo-file-system)                                                                               | См. `ui-parity-exceptions.json` — тип выбранного файла платформенный                                                                                                   |
| `BugReportButton` | `<Dialog>` (`@base-ui/react/dialog`) + кнопка «приложить снимок» (ручной файл, без автоматики — раздел "Фаза 9" задания, пункт 9.1) | `Modal` (react-native) + обязательный проп `captureScreenshot` (react-native-view-shot на стороне apps/mobile, снимок автоматический) | `captureScreenshot` есть только у ui-native — на вебе DOM-снимки ненадёжны (внешние шрифты/canvas/кросс-доменные картинки), поэтому там только ручное приложение файла |

`pnpm check:parity` сверяет СОСТАВ экспортов `src/index.ts` обоих
пакетов по именам (`export { A, type B }`) — расхождение без записи в
`ui-parity-exceptions.json` роняет гейт (сделано в Фазе 8, было
заглушкой до неё).

## Почему `buttonVariants` не идентичен между платформами

`packages/ui-core/src/button-variants.ts` отдаёт только
кросс-платформенные утилиты — `hover:`, `transition-colors`,
`[&_svg]` и подобные веб-only понятия Tailwind остаются в
`ui-web/button.tsx` отдельным `cva` (`webOnlyVariants`), накладываемым
поверх общего. Подробности — `docs/packages/ui-native.md` и
`docs/BACKLOG.md`, `B-261008-button-variants-web-only-modifiers`.

## Подписи (`labels`)

`BugReportButton` и `FileUpload` в обоих пакетах принимают проп `labels`
одного и того же типа (`BugReportLabels`, `FileUploadLabels` из
`@boilerplate/ui-core`). Незаданные ключи остаются русскими. Часть ключей
нужна только одной платформе (`attachScreenshot` у веба, `pickFile` у
мобильного), тип общий, чтобы набор подписей совпадал по построению.
Как приложения передают переводы — [guides/i18n.md](../guides/i18n.md).

## Исключения

`ui-parity-exceptions.json` в этой же директории — список точек,
где платформенное API делает тождественность пропсов невозможной
или вредной (и почему). Любое новое исключение — строка с коротким
обоснованием, не просто имя компонента.
