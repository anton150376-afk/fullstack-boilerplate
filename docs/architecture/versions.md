## Выравнивание под Expo SDK 57

`npx expo-doctor` в `apps/mobile` сверяет объявленные пакеты с
`expo/bundledNativeModules.json`. Каталог по умолчанию брал самые свежие
версии, поэтому `expo-doctor` находил расхождения. Выровнено (2026-10-11):

| ---------------------------------- | ------ | ------------------------------------------------------------------------------------ |
| `react`, `react-dom`               | 19.2.3 | Версия, которую требует SDK 57; рендерер внутри `react-native` 0.86 собран под неё   |
| `@types/react`, `@types/react-dom` | 19.2.x | Та же ветка, что `react`                                                             |
| `react-native-view-shot`           | 5.1.0  | Версия SDK 57; каталог держал мажор 6                                                |
| `react-native-reanimated`          | 4.5.1  | Нативная пара; без явного объявления pnpm ставил `worklets` 0.13 вместо 0.10.1       |
| `react-native-worklets`            | 0.10.1 | Нативная пара `reanimated`, версия SDK 57                                            |
| `@react-native/metro-config`       | 0.86.3 | Peer-зависимость `community-cli-plugin` 0.86.3; без версии pnpm брал 0.87            |
| `metro-resolver`                   | 0.84.5 | `metro.config.js` подключает его напрямую, раньше он не был объявлен                 |

Веб-приложение и серверные пакеты берут `react` из того же каталога, поэтому
весь репозиторий на 19.2.3: одна версия React без дубликатов (грабля 4
задания). После правки `expo-doctor` проходит 21 проверку из 21, а
`pnpm peers check` не показывает мобильных несовпадений.

## Риски и расхождения, вынесенные в `docs/BACKLOG.md`

1. **Docker недоступен на машине агента.** Фазы 4 и 10 потребуют его для
   `docker compose up`, интеграционных тестов и сборки образов — это нельзя
   проверить до установки Docker Desktop или аналога.
2. **Vite 8 и `@tanstack/react-start`.** Закрыто, проект на Vite 8.3.4.
   Задание фиксировало Vite 7.x из-за поломки `TanStack/router#7614`
   (SSR-мидлвар молча не регистрируется, запрос падает в `Cannot GET /`).
   Issue закрыт 2026-09-07 ссылкой на исправление в `vite-plus`, поэтому для
   обычного Vite 8 это ничего не доказывало, и версию проверили
   экспериментом (2026-10-11): с Vite 8.3.4 и `@vitejs/plugin-react` 6.1.2
   на `@tanstack/react-start` 1.168.60 собираются клиент и сервер, dev-сервер
   отдаёт страницы `/files` и `/admin/system` (200) и страницу 404 нашего
   приложения, собранный `server-entry.mjs` делает то же, 13 тестов веба и
   полный `pnpm gate` проходят. Дефект не воспроизводится.
3. **`@nestjs/bullmq` 12.0.0 vs 11.0.5 в задании.** Закрыто: журнал
   изменений прочитан, публичный API не изменился, 12.0.0 — единственная
   версия с поддержкой Nest 12. Подробности —
   [ADR-0003](decisions/ADR-0003-nestjs-bullmq-version.md).
4. **Garage: версия образа.** Закрыто. Тег `v1.0.1` из задания существует
   (опубликован 2024-09-22), но актуальный стабильный — `v2.4.1`
   (2026-09-08); тегов `v2.4.2` и `v2.5.0` нет. Образ берётся из
   мультиархитектурного репозитория `dxflrs/garage` (amd64, arm64, arm,
   386), а не из `dxflrs/amd64_garage`. Флаги `--single-node` и
   `--default-bucket` появились в v2.3.0, у `v1.0.1` их нет. Подробности
   и найденная ошибка запуска — `docs/guides/docker.md`.
5. **`prismaSchemaFolder` — уже GA, не preview.** С Prisma 6.7.0 фича вышла
   из `previewFeatures`; в Prisma 7.x расположение схемы настраивается через
   `prisma.config.ts`, а не только флагом в `schema.prisma`. Задание исходит
   из более старой модели — учесть при настройке в Фазе 1/4.
6. **react-i18next 17.0.16 — версия не была подтверждена заданием**, теперь
   зафиксирована.
7. **`@aws-sdk/client-s3` версии 3.11xx.x** — на порядок выше номеров, на
   которые ссылается грабля про чек-суммы (issue упоминает 3.729.0). Дефолт
   `requestChecksumCalculation: WHEN_SUPPORTED` подтверждён официальной
   документацией AWS SDK Reference на дату проверки — отключение обязательно
   остаётся в силе.
