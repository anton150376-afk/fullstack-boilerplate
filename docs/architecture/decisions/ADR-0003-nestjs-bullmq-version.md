# ADR-0003: Версия `@nestjs/bullmq`

> **Статус:** принято
> **Дата:** 2026-10-11

## Контекст

Задание называет `@nestjs/bullmq` 11.0.5 рядом с `@nestjs/*` 12.0.0 (раздел 4,
таблица версий), а в реестре последняя версия адаптера — 12.0.0. В проекте
стоит 12.0.0 с Фазы 4 (`apps/server/package.json`), а BullMQ взят 6.3.11
вместо 6.3.6 из задания. Расхождение записано как
`B-261008-bullmq-nest-major`: нужно было сверить журнал изменений и решить,
какая версия остаётся и не сломал ли мажор публичный API.

## Решение

**`@nestjs/bullmq` 12.0.0 с BullMQ 6.3.11.** Это единственная версия адаптера,
которая объявляет поддержку Nest 12, а проект на Nest 12 по решению D2/D3 из
[ADR-0001](ADR-0001-stack.md). Версия 11.0.5 потребовала бы понизить Nest.

Ломающие изменения мажора проверены по факту, не только по заметкам к релизу:

- Сравнены `dist/index.d.ts` версий 11.0.5 и 12.0.0 из опубликованных
  пакетов. Публичный API совпадает (`BullModule`, `InjectQueue`, `Processor`,
  `WorkerHost`, `getQueueToken`, `JOB_REF`). Файлы, пропавшие из пакета
  (токены очередей, ошибка общей конфигурации, `helpers`), переехали в
  `@nestjs/bull-shared`.
- Код проекта импортирует из пакета только `BullModule`, `InjectQueue`,
  `Processor` и `WorkerHost`, все четыре из корня пакета
  (`apps/server/src/queue/*`). Глубоких импортов нет.
- `pnpm peers check` не сообщает о несовпадениях по `bullmq` и `@nestjs/*`.
- Под Node 22.22.1 пакет импортируется через `import`, а `require()` из
  CommonJS тоже работает (`require(esm)`).
- Сервер уже ESM (`"type": "module"`, `moduleResolution: nodenext` в
  `packages/typescript-config/node.json`), поэтому условие `exports` пакета
  соблюдается без изменений.

## Последствия

- Импортировать `@nestjs/bullmq` и `@nestjs/bull-shared` только из корня
  пакета. Глубокие пути перестали разрешаться.
- `engines.node: ">=22"` допускает Node 22.0–22.11, где `require()` ESM-пакета
  выключен по умолчанию. Сервер использует `import`, поэтому не затронут.
  Затронули бы CommonJS-скрипты в репозитории, если бы они подключали
  адаптер. Поднимать `engines` до 22.12 сейчас не нужно.
- Откат на 11.0.5 невозможен без понижения Nest до 11. Если мажор 12
  окажется сырым, откат дорогой.
- Живой прогон очередей против Redis не выполнялся: на машине сборки нет
  Docker (`B-261008-no-docker`, `B-261008-docker-unverified`). Поведение
  покрыто тестами с подменой (`notifications.processor.spec.ts`,
  `maintenance.processor.spec.ts`) и проверкой импорта под настоящим Node.
  Первый прогон с Redis должен заново проверить постановку задач и
  Job Scheduler.
