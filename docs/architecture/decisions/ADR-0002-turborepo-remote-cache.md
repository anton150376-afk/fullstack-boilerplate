# ADR-0002: Удалённый кеш Turborepo

> **Статус:** принято, требует подтверждения на практике
> **Дата:** 2026-10-08

## Контекст

Раздел "Фаза 10" задания, пункт 10.2 — удалённый кеш Turborepo нужен,
чтобы второй участник и CI не пересобирали то, что уже собрано на
другой машине; выбор между бесплатным кешем Vercel и своим оставлен
агенту. `.github/workflows/ci.yml` уже читает `TURBO_TOKEN`/`TURBO_TEAM`
из секретов/переменных репозитория — без них задачи просто пересобираются
с нуля, без ошибки, поэтому выбор ниже можно включить позже, не меняя
сами workflow.

## Рассмотренные варианты

| Вариант                                                  | Плюсы                                                                                                                                        | Минусы                                                                                           | Источник                                                                  |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| Remote Cache Vercel                                      | Бесплатен на всех планах, в том числе без хостинга приложений на Vercel; нулевая настройка (`vercel login`/`turbo link` или два токена в CI) | Артефакты сборки уходят за пределы инфраструктуры репозитория; не подходит air-gapped окружениям | turborepo.dev/docs/core-concepts/remote-caching, changelog Vercel 2026    |
| Свой сервер (`ducktors/turborepo-remote-cache` и схожие) | Данные остаются в своей инфраструктуре; соответствует требованиям, где внешний кеш запрещён                                                  | Нужно поднимать и поддерживать отдельный сервис (хранилище, авторизация, резервные копии)        | тот же раздел документации Turborepo, README соответствующих репозиториев |

## Решение

**Remote Cache Vercel** по умолчанию — для этого шаблона нет требования
держать артефакты сборки внутри своей инфраструктуры, а бесплатный и
не требующий отдельного сервиса вариант снижает число подвижных частей
в CI. `TURBO_TOKEN`/`TURBO_TEAM` в `.github/workflows/ci.yml` уже
готовы принять токен Vercel как есть. Самостоятельный сервер — пункт
ROADMAP, если появится комплаенс-требование не выпускать артефакты
сборки за периметр.

## Последствия

Отменить дёшево: без токенов CI просто не кеширует между запусками
(не ошибка, не сбой гейта) — включение Vercel Remote Cache позже не
требует правки workflow, только добавления секрета/переменной в
настройках репозитория. Непроверено вживую — токен Vercel ни разу не
создавался и не прогонялся в этой сессии (`docs/BACKLOG.md`,
`B-261008-no-remote-repo`): этот ADR — решение, не подтверждённая
практика.
