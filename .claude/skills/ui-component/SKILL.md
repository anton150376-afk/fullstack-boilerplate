# ui-component

## Шаги

1. **Варианты в `ui-core`.** Логика вариантов (`variant`, `size`, состояния)
   — платформенно-независимая, без JSX и без привязки к Tailwind/Uniwind.
2. **`ui-web`.** Компонент на Base UI, стили — классами Tailwind со
   ссылкой на токены `packages/tailwind-config` (`.claude/rules/ui.md`).
3. **`ui-native`.** Тот же набор пропсов и то же имя, стили — классами
   Uniwind. Бесплатная ветка не поддерживает `hover:`/`group-*` — не
   использовать в общих примитивах.
4. **Паритет.** Обновить таблицу «компонент → в `ui-web` → в `ui-native` →
   расхождения» в `docs/packages/ui.md`. Расхождение — только с причиной,
   не молча.
5. **Тесты.** Рендер в обоих пакетах через `@boilerplate/testing` (пресет
   `dom` для `ui-web`); состояния: по умолчанию, ошибка, загрузка,
   пустота, если применимо.
6. **Гейт.** `pnpm check:parity` зелёный; `pnpm verify`.
