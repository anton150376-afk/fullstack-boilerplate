# bug-triage

## Шаги

1. **Контекст.** Прочитать markdown-отчёт: маршрут, версия сборки,
   платформа, буфер последних запросов с `request-id`, трейл действий,
   снимок состояния TanStack Query.
2. **Логи.** Найти серверные записи pino по `request-id` конкретного
   запроса из буфера — это главная причина, по которой `request-id`
   вообще собирается.
3. **Воспроизведение.** Локально, по шагам из отчёта.
4. **Падающий тест.** Сначала тест, который фиксирует поломку, потом
   исправление.
5. **Починка.** По правилу, соответствующему затронутой области
   (`.claude/rules/`).
6. **Закрытие.** Пункт `docs/BACKLOG.md`, заведённый по итогам разбора
   (если отчёт не был заведён как пункт раньше), переводится в «Закрыто» с
   коммитом. Отчёт — из `.bugs/` в `.bugs/closed/`.
7. **Гейт.** `pnpm verify`.

Маскирование секретов в самом отчёте (`Authorization`, токены, пароли) —
забота ядра `packages/devtools`, не этого скилла; если секрет всё же
попал в отчёт — это отдельный, более приоритетный пункт бэклога про сам
механизм маскирования, а не про найденный баг.
