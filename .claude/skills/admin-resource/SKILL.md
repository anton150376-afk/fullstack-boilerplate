# admin-resource

## Шаги

1. **Реестр.** `defineResource({ name, routes, columns, filters, form,
permissions })` в `packages/admin-kit` — маршруты берутся из
   `packages/contract`, не дублируются (`.claude/rules/admin.md`).
2. **Поля формы.** Выводятся из Zod-схемы маршрута через `.meta()`.
   Честная граница: `.refine()`/`.superRefine()`, размеченные объединения
   и вложенные структуры — не генерируются, переопределяются вручную
   через `form.overrides`.
3. **Таблица.** `manualPagination`/`manualSorting`/`manualFiltering` —
   данные приходят с сервера, таблица ничего не вычисляет сама. Состояние
   — в параметрах поиска (`validateSearch` на схеме Zod 4 напрямую).
4. **Права.** Через интерфейс поставщика прав, не прямой проверкой роли.
5. **Демонстрационные данные.** Если ресурс показательный — сиды
   `db:seed:demo` на серверной стороне (вне ответственности этого скилла,
   если сиды уже существуют).
6. **Тесты.** Список с пагинацией/сортировкой/фильтрами, создание,
   изменение, удаление; форма отвергает то, что отвергает сервер.
7. **Гейт.** `pnpm check:parity` (admin-kit в исключениях, паритет не
   требуется); `pnpm verify`.
