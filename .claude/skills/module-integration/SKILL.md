# module-integration

Процедура раздела 15 `docs/architecture/original-task.md` — здесь только
шаги, критерии сравнения библиотек и общие требования смотреть там.

## Шаги

1. **Рамка.** Прочитать пункт ROADMAP, применимые `.claude/rules/*.md` и
   `docs/modules/<модуль>.md`. Что входит в этап, что явно нет.
2. **Исследование.** Подагентом `researcher` найти 3–5 решений, таблица по
   критериям раздела 15.2 (лицензия, статус проекта, активность, зрелость,
   автобусный фактор, типизация, совместимость, автономность, стоимость
   выхода, размер). Отдельно проверить, не сменился ли статус проекта —
   свёрнут, куплен, перелицензирован.
3. **Решение.** Готовое / готовое с адаптером / своя реализация. ADR с
   таблицей вариантов, выбором, последствиями, датой.
4. **План.** 3–7 проверяемых шагов, пункты `docs/BACKLOG.md`.
5. **Ядро.** `packages/<модуль>`, платформенно-независимая часть,
   подключение в `apps/server`. Публичный интерфейс — через
   `packages/contract`.
6. **Интерфейсы.** Минимум, предусмотренный этапом, в веб и мобильное —
   через общую фабрику и парные компоненты (`.claude/rules/client.md`,
   `ui.md`).
7. **Тесты.** Unit на ядро, интеграционные на серверную часть, сценарные
   на интерфейсы.
8. **Документация.** `docs/modules/<модуль>.md` из «не реализовано» в
   описание устройства. Обновить `docs/operations/env-vars.md` и гайды.
9. **Закрытие.** Статус этапа, закрыть пункты бэклога, `pnpm gate`,
   остаток — в новые пункты бэклога.

## Общие требования к любому модулю

Не зависит от конкретного поставщика (адаптер по одному интерфейсу);
переживает перезапуск (состояние в PostgreSQL, фон — в очередях); внешние
вызовы идемпотентны с таймаутом; выключается флагом и не мешает
выключенным; публичные события описаны для подписки другими модулями.
