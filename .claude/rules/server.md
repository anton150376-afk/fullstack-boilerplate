# Серверный код

- Структура модулями-вертикальными срезами:
  `module/{controller,service,repository,dto,tests}`. Новый модуль
  повторяет эту раскладку, а не изобретает свою.
- Доступ к базе данных — **только** через репозиторий своего модуля.
  Сервис и контроллер Prisma напрямую не вызывают.
- Транзакции явные (`prisma.$transaction`), не полагаться на то, что
  несколько запросов подряд образуют одну логическую операцию.
- Валидация — на границе: DTO/схема контракта проверяет вход до того, как
  он дойдёт до сервиса.
- Токены, пароли и прочие секреты **никогда** не попадают в логи pino —
  ни в сообщении, ни в объекте контекста.
- Пакет воркспейса, который нужен серверу в рантайме (`workspace:*` в
  `apps/server/package.json`), обязан иметь скрипт `build`, файл
  `tsconfig.build.json` и условие `compiled` в `exports` у каждой точки
  входа: в продакшене сервер запускается как
  `node --conditions=compiled`, иначе падает на первом импорте.
  Проверяет `pnpm check:runtime`.
- Идентификатор задачи BullMQ (`jobId`) — без двоеточия.
- Новый вид ошибки 5xx должен попадать в журнал: перехватчик `onError`
  в `app.module.ts` делает это для oRPC; не глушите исключения молча.
- Подробнее об устройстве — `docs/apps/server.md`.
