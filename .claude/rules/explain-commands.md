# Команды для владельца — с пояснениями

Правило владельца, действует во всех проектах на основе. Подгружается всегда
(без `paths`): касается любого ответа, где владельцу нужно что-то выполнить
самому.

Владелец не силён в командах Linux и PowerShell и учится постепенно. Если для
шага нужно, чтобы он сам что-то выполнил («слейте #7, потом #8», «перезапустите
сервис»), одних слов мало. Всегда давать:

1. **Точные команды.** Готовые к копированию, по одной на шаг, в порядке
   выполнения.
2. **Где выполнять.** Какой терминал (PowerShell на ПК, консоль сервера по
   ssh), какой каталог, нужны ли права (`sudo`/root).
3. **Что делает каждая команда и каждый ключ.** Коротко, по-русски; что
   считать успехом, а что ошибкой.
4. **Чем грозит ошибка и как откатить,** если команда меняет состояние
   (слияние, удаление, перезапуск).

Пример: «В PowerShell, в каталоге репозитория: `gh pr merge 7 --squash` — `gh`
это консольный GitHub, `pr merge 7` сливает запрос №7 в основную ветку,
`--squash` склеивает его коммиты в один. Успех — строка
`Merged pull request #7`».

Команды для вставки в консоль, где длинные вставки ломаются, — одной строкой и
только ASCII.
