# Очереди (BullMQ)

- Идемпотентность: детерминированный `jobId` плюс ключ идемпотентности,
  записываемый в Postgres в одной транзакции с побочным эффектом задачи.
- Лимит повторов с экспоненциальной задержкой — не оставлять задачу на
  бесконечные повторы.
- Логировать начало и конец обработки задачи (с её идентификатором) —
  это основной источник диагностики при разборе багрепорта.
- Падение одной задачи не роняет процесс воркера — ошибка ловится внутри
  обработчика, воркер продолжает забирать следующие задачи.
- Расписания — только через Job Schedulers. Опции `utc` не существует
  (`tz: 'UTC'` вместо неё), свой `jobId` для расписания задать нельзя.
- Воркер — отдельный процесс (`NestFactory.createApplicationContext`, без
  HTTP-адаптера), не часть HTTP-процесса API.
- Подробнее — `docs/apps/server.md` (появится в Фазе 4).
